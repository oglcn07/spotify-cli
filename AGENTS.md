# Repository Guidelines

## Communication & Project Vibe

This is a relaxed personal project. Chat with the owner in casual Turkish; friendly expressions like "cano" and occasional emojis are welcome. Match their energy naturally, keep explanations short and clear, and avoid forced slang. Stay precise about code changes, errors, and verification.

## Project Structure & Module Organization

This is a small Linux CLI for controlling Spotify from the terminal. `spotify.py` contains command dispatch, Soloist playback controls, Spotify API searches, device discovery, and the curses watch UI. `test.py` is an interactive API smoke script. `test_watch.py` contains offline unittest regression checks. `watch_config.py` stores each user's Web API Client ID and private OAuth cache; `install.py` creates the local launcher and service. `setup_soloist.py` saves the Soloist key privately; `HEADLESS.md` explains setup. `.venv/` holds the local Python environment; `__pycache__/` contains generated bytecode. Files named `spotify.py.bak*` and `spotify.py.before_*` are historical snapshots; make changes to `spotify.py`.

The external launcher at `~/.local/bin/spotify` invokes this directory's virtual environment and forwards command arguments.

`watch_settings.py` validates and atomically saves cover mode, artwork visibility,
and volume to `~/.config/spotify-cli/preferences.json`. Watch restores these on
startup. `k` shows a local queue snapshot, `e` enqueues the selected/current track,
`f` browses Spotify saved tracks with `[`/`]` pagination, `l` saves a track,
`?` shows help, `v` toggles artwork, and `+`/`-` change volume. Library jobs run
in WatchAPI with separate lazy library scopes; `spotify login` authorizes those
outside curses. Keep search usable with the original playback-only scopes.
`save_track` uses Spotipy's `_put` adapter for the current `me/library` endpoint
because the installed version has no public library wrapper.

`watch_art.py` loads album artwork in a separate worker with an eight-cover memory cache and renders a right-side panel. It hides below 90 terminal columns; `a` cycles 8-bit, detailed 16-bit-style half blocks, Glitch, and ASCII. Glitch deliberately preserves the original color aliasing. Normal modes must keep `curses.color_pair()` IDs below 256 even when `COLOR_PAIRS` is larger. Keep curses drawing on the UI thread.

## Build, Test, and Development Commands

Run these commands from `~/spotify-cli`:

- `.venv/bin/python spotify.py`: print usage without changing playback.
- `spotify watch`: show live metadata, progress, and API playback context. Space toggles playback; `n`/`p` skip next/previous. `/` searches tracks; arrows select a result and Enter plays it. Esc cancels search; `q` or Ctrl+C exits. Controls and playlist context use local `soloist ctl`; search uses a background API worker with cached OAuth credentials. Commands start `soloist.service` on demand and never launch desktop Spotify.
- `.venv/bin/python -m py_compile spotify.py setup_soloist.py test_watch.py`: check syntax.
- `.venv/bin/python -m unittest -v test_watch`: run offline regression checks.
- `.venv/bin/python test.py`: run a live search; may open a browser for authorization and update `.token-cache`.
- `spotify play "Demir Demirkan Zaferlerim"`: search for and play a track.
- `spotify play --album "album name"` or `spotify play --playlist "playlist name" --shuffle`: play a collection.
- `spotify pause`, `spotify resume`, `spotify next`, `spotify now`, and `spotify volume 50`: control or inspect the windowless player.

There is no build step. Install Python dependencies with `.venv/bin/python -m pip install -r requirements.txt` (Spotipy and Pillow). Playback requires official Spotify Soloist at `~/.local/bin/soloist` and a systemd user session with PipeWire/PulseAudio. User service: `~/.config/systemd/user/soloist.service`.

## Coding Style & Naming Conventions

Use four-space indentation, `snake_case` functions and variables, and uppercase constants. Follow existing Python formatting; no formatter or linter is configured. Keep terminal messages in Turkish. Preserve existing command aliases and Unicode-aware search matching.

## Testing Guidelines

Use standard-library unittest; no coverage threshold is configured. Mock Spotipy, subprocess calls, and timing in offline tests. For playback changes, verify affected commands against a paired Soloist instance and record results. Live checks can change playback and require network access.

## Commit & Pull Request Guidelines

This directory uses Git. Use concise imperative commit subjects. Describe behavior changes, affected commands, and validation in pull requests; include terminal output when useful.

## Security & Configuration

Never commit or expose `.token-cache`, which stores OAuth credentials. Exclude `.venv/`, `__pycache__/`, and backup snapshots from future commits. Never expose `~/.config/soloist/soloist.env` or Soloist session data. Soloist builds expire after 90 days; use official downloads to update. The stopped Spotifyd experiment failed with an upstream audio-key error; do not treat it as working.
